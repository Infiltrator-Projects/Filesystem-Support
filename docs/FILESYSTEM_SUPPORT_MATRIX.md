# Filesystem Support Target Matrix

This document is the human-readable support contract for **Filesystem Support**.

It mirrors the 108 entries compiled into `src/catalog.cpp`. Every row is something the project intentionally aims to detect and manage. The action model distinguishes packages, userspace/FUSE implementations, DKMS drivers, loadable kernel modules and filesystem code compiled directly into the running kernel.

**Baseline:** Debian stable (Debian 13 “trixie” when this matrix was updated)  
**Catalogue entries:** 108  
**Code source of truth:** `src/catalog.cpp`  
**Documentation invariant:** CI verifies that every catalogue ID has exactly one unique `support-<id>` row anchor in this matrix.

## Action semantics

- **Project-native kernel module:** **Install native** compiles the canonical filesystem plus Linux adapter against the running kernel, installs the resulting `.ko` under `/lib/modules/<kernel>/updates/infiltrator/`, runs `depmod`, loads it with `modprobe`, and verifies the project module was selected. **Remove native** refuses while the module is in use, unloads it, removes only the Infiltrator-owned `.ko`, and runs `depmod` again. Administration packages such as `e2fsprogs` are separate and never count as installing the filesystem driver.
- **Kernel driver:** no Debian filesystem package is owned by this row. If the driver is a loadable module, the UI offers **Load module** / **Unload module**. If it is compiled into the running kernel, the UI reports **Built into kernel**. If the running kernel does not provide it, the UI reports **Requires different kernel**.
- **Kernel + Debian userspace:** kernel availability and userspace utilities are separate. The package button installs/removes tools; the kernel button independently reports or manages the module.
- **DKMS driver + Debian packages:** the Debian package set supplies the out-of-tree driver. Install/remove therefore manages the actual driver package as well as its userspace components.
- **Userspace / FUSE package:** install/remove manages the filesystem implementation itself.
- **Tools only:** install/remove manages direct inspection/manipulation tools; it does not claim a normal mount driver.

Package removal is simulated before privilege escalation. Removal is refused when Debian's plan includes a package outside this catalogue or a package marked Essential, Protected, or priority `required`. The application never runs `autoremove` automatically. Shared catalogue packages are shown in the confirmation dialog through all affected catalogue IDs.

## Project rule

When support is added, removed or materially changed in `src/catalog.cpp`, this matrix must be updated in the same commit. CI treats a missing or duplicated support-row anchor as a failure.


## Long-term native-provider policy

The **Support path** column above describes the provider available to Filesystem Support today. It is not necessarily the project's final implementation.

For conventional local filesystems, the long-term goal is an Infiltrator-owned loadable Linux VFS module managed by Filesystem Support, with no custom kernel requirement and no FUSE process in normal operation.

High-level cloud, network, archive and device protocols may remain userspace-backed when moving their TLS, authentication or application-protocol stacks into the kernel would be technically unsound. Those targets should converge on a shared Infiltrator userspace storage service rather than a multitude of unrelated helpers.

The complete policy is defined in [`NATIVE_FILESYSTEM_VISION.md`](NATIVE_FILESYSTEM_VISION.md).
